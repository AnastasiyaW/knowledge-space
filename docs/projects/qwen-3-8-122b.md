# Qwen

Qwen 3.8 122B can be fine-tuned locally in Strata on a 16 GB VRAM GPU with 64 GB RAM, without a multi-GPU cloud cluster.

**Development line:** project:qwen-3-8-122b · thread qwen-model-and-capability-releases  
**Last event:** 2026-11-20 · 4 dated since 2026-03-03 · **Researched:** 2026-11-21 · confidence: medium

## What it is

Qwen 3.8 122B local fine-tuning in Strata tunes a 122-billion-parameter language model on a consumer workstation. The usual route is a multi-GPU cloud cluster. This one needs neither.

How it works:

- It freezes 48 base transformer layers.
- It computes and caches activation tensors on the graphics processor.
- It runs supervised fine-tuning (SFT) and direct preference optimization (DPO) on a compact output module, using system memory.
- It restores the original weights with automated rollback scripts.

Limits: 16 GB of video memory and 64 GB of system memory. Only the final module changes, and internal representations are not updated. The result is behavioral alignment for local agents without enterprise training hardware.

## What changed

Strata used to serve inference only. Training now runs locally, with forward activation caching kept apart from output parameter updates.

The first experiments showed that the main layers can stay frozen on a consumer graphics card while the CPU optimizes a compact output head. Supervised fine-tuning and preference alignment passes came next, along with automated checks on local agent workloads.

## How to use this

1. Deploy the base Qwen 3.8 122B model in the Strata inference engine on a workstation with at least 16 GB VRAM and 64 GB system RAM.
  — <https://habr.com/ru/articles/1110182/>
2. Freeze the 48 main transformer layers. Route training dialogues through the GPU forward pass to cache intermediate activations.
  — <https://habr.com/ru/articles/1110182/>
3. Run SFT and DPO training on the CPU, and only on the 12.54 MiB output module.
  — <https://habr.com/ru/articles/1110182/>
4. Check the changes against the laboratory agent. Keep the rollback script so the output module can be reverted if results regress.
  — <https://habr.com/ru/articles/1110182/>

## Best practices

- Cache forward-pass activations on the GPU before CPU training starts, so VRAM does not run out and there is no full backpropagation through frozen layers.
  — <https://habr.com/ru/articles/1110182/>
- Keep the automated rollback scripts, so the base output-module weights come back at once if agent evaluations get worse.
  — <https://habr.com/ru/articles/1110182/>
- Keep local CPU fine-tuning to light alignment passes such as SFT and DPO, so a cycle stays near one minute.
  — <https://habr.com/ru/articles/1110182/>
